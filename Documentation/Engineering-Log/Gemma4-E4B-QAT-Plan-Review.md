# E4B QAT execution-plan review

2026-09-25 · Local checkout and upstream documentation review only. No execution gates were tested. References below are relative to this repo; `Plan` and `Progress` denote the adjacent migration documents, and `Services` denotes `Angrove-iOS/Services`.

**Verified upstream facts:** HF lists [GPU 2.97 GB and standard 3.66 GB packages](https://huggingface.co/litert-community/gemma-4-E4B-it-litert-lm/tree/main). The [mobile-QAT source repository](https://huggingface.co/google/gemma-4-E4B-it-qat-mobile-transformers/tree/main) lists a 3.53 GB safetensors file, not a `.litertlm`. Neither filenames nor those sizes establish E4B QAT provenance. The [published iPhone 17 Pro results](https://huggingface.co/litert-community/gemma-4-E4B-it-litert-lm) use the 3.66 GB package, cached initialization, 2,048 context, 1,024 prefill and 256 decode tokens—not the proposed GPU artifact, base phone, or 4,096-token app configuration. Local package metadata supports the listed converter versions; that is not conversion validation.

1. **Blocker — C2/C8: provenance is not a dtype test.** Plan:171 and :375 allow classification from quantization signals, then promotion under a QAT label. [Issue #2497](https://github.com/google-ai-edge/LiteRT-LM/issues/2497) remains open without a published answer; its question is not evidence that packages are non-QAT. **Change:** require artifact-specific maintainer/source lineage for “QAT”; keep unknown candidates eligible for investigation, but require an explicit scope decision before promoting them as an alternative. Keep D4; replace its categorical “discard QAT benefit” rationale with “quantization fidelity is unverified.”

2. **Blocker — C3b: unsupported conversion is presented as an executable fallback.** `../Aquinas-Foundations/research/gemma-4-qat/compatibility.md:8` records missing mobile-schema import/preservation support. [LiteRT Torch documentation](https://github.com/google-ai-edge/litert-torch/blob/main/README.md) describes the builder as packaging already converted graphs and tokenizers, not importing QAT weights. **Change:** inspect pinned exporter support before downloading; require a documented schema-preserving route, bounded investigation budget, and tokenization/numerical export checks. Otherwise mark this route blocked. FP16 preference alone does not preserve static activation scales or mixed-width quantization.

3. **Should-fix — C3a/C6: probe contracts contradict the instructions.** `Angrove-iOS/Features/Developer/LiteRTDeviceProbe.swift:108` sets raw context to 2,048; :121 samples at temperature 0.2; :143 hardcodes prudence. Only quality mode reads `--litert-probe-question` (:190), and `--litert-probe-cpu` affects only raw mode (:104). **Change:** add explicit deterministic raw/context/question controls before using these gates, record effective settings, and separate informational sampling. C3a must specify the prudence question flag for quality mode.

4. **Should-fix — C3a/C7: simulator failure is not phone failure.** Plan:214 concludes a simulator GPU failure prevents Metal shipping. `../Aquinas-Foundations/MODEL-INTEGRATION.md:96` documents an FP32 slowdown for a different export, not every E4B graph. **Change:** classify simulator buffer/kernel failures separately and permit a bounded physical-device compatibility check. Record actual delegate and activation resolution; distinguish a supported quantized graph from an unintended FP32 fallback instead of treating every non-FLOAT16 signal identically.

5. **Blocker — C7: memory acceptance is not measurable.** Plan:344–357 specifies 20 turns and survival without a footprint ceiling or full-context workload. **Change:** insert early disposable-phone load/short/2K/4K screening before expensive C6 scoring. Freeze a numeric process physical-footprint cap with headroom; measure load, full-context prefill, decode, teardown, MiniLM/app overhead and largest GPU allocation. Carry over the older plan’s cap/headroom rule (`../Aquinas-Foundations/GEMMA-4-QAT-EVALUATION-PLAN.md:416`). Eight GB total RAM and Pro benchmarks are not the app’s memory budget.

6. **Should-fix — C7: latency thresholds need a protocol.** Plan:353–359 lacks repetitions, timing boundaries, output budgets and a cached-load baseline. **Change:** retain thresholds as provisional product budgets; freeze cold/cache definitions, input/output lengths, repeated trials, p95/max, thermal conditions and visible-answer versus metadata completion timing. Define sustained degradation limits and recovery after the deliberately induced warning. Do not call every threshold “2–3× baseline.”

7. **Blocker — C5/C7: logical cancellation may leave native work alive.** `Services/LiteRTAngroveRuntime.swift:124` retains orphaned native work; :374 describes watchdog abandonment. The risk is overlapping native allocations during reload, not proof that overlap has occurred. **Change:** require cancel/preempt/timeout/background/idle-unload followed by a successful new request, no stale UI updates, bounded memory recovery, and evidence that native engines do not overlap unsafely. A 400 ms teardown delay (:279) is not that evidence.

8. **Blocker — C6: ties on eleven familiar prompts do not establish improvement.** Plan:318 accepts mean equality; marker counts do not prove valid links or grounding. The quality probe constructs a single-turn transcript (:194), so the multi-turn cases cannot run as written. **Change:** implement conversation fixtures, freeze retrieval/history/budgets, score valid supported links and category regressions, and predeclare meaningful improvement plus absolute quality floors. Carry over development/held-out separation and uncertainty reporting from the older plan:121. Its 60/200-case proposal can be resized explicitly, not silently replaced by smoke tests. Baseline malfunction must not lower acceptance standards.

9. **Should-fix — C5/C9: diagnose integration before blaming quality.** Plan:293 calls structured failures quality failures. **Change:** verify E2B/E4B tokenizer, rendered roles, EOS/channel handling, truncation and structured schemas first; separate retrieval, parsing and model failures. `Services/LiteRTAngroveRuntime.swift:275` disables vision: test graceful handling of existing image-bearing history and attachments in text-only mode. Keep optional vision outside release acceptance and do not strip modality tensors without a supported export.

10. **Should-fix — C0/C1/C4/C8: identity and final deployment need closure.** `Services/LiteRTModelStore.swift:64` accepts development files by size; :68 prioritizes Application Support over the bundle. Plan:388 only retests the final configuration on simulator. **Change:** pin HF revision and compare authoritative file hash, provision ignored assets explicitly into the clean worktree, and record baseline commit/dirty exclusions. Share a Documents resolver between probe/full-app overrides. Verify loaded URL/hash and complete a final no-override phone smoke plus rollback check using the packaged artifact.

11. **Should-fix — resume rules/C3b/ledger: checkpoint state is not candidate state.** Plan:10 selects the first status other than `done`, but Progress:8 includes `skipped`; C3b can return to a prebuilt after C6 already failed (Plan:243). **Change:** select eligible dependencies, recognize intentional skips, and track candidate hash/runtime/config/run IDs with immutable evidence paths and exact commands. New artifacts invalidate dependent gates; blocked conversion cannot erase failed quality. Specify the isolated Backend workspace for the export script and reconcile disk reserves with the older plan before conversion.

**Verdict: ready after the listed fixes.** Baseline inventory can proceed once authorized; the present gates are insufficient for candidate rejection or promotion. No fine-tuning or shelved research is needed to address these findings.
